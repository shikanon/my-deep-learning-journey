## 为什么过去只看到了“402”

已阅读当前安装的连接器 HTTP 适配代码。非 200 响应分支只将状态码、request_id 和 x-tt-logid 放进异常；它没有保存服务端错误正文、业务错误码或业务描述。这解释了为什么旧报错无法进一步区分账户状态、计费项或资源限制。

旧失败的 request_id 为 `1095601c-7281-43d8-8d00-13c4b04e97b0`，log_id 为 `20261002102425014C3BF18543988167B2`。这些追踪 ID 可以帮助服务方查询当时的请求。缺失的响应正文无法从旧 manifest 还原。

**结论：本轮 402 没有复现，当前四次实际生成成功；旧请求的确切根因未能追溯。上一版将它直接归为“额度不足”的判断应撤回。** HTTP 402 本身不足以说明哪一种额度用完，也不能把别的产品额度当成当前计费项额度。

官方 [豆包语音计费与到期 / 欠费说明](https://www.volcengine.com/docs/6561/1359394)要求资源包适用于对应计费项且处于有效期内。该规则只是诊断背景，不是本次失败根因的证据。

建议连接器在将来失败时保留经过脱敏的 HTTP 状态、业务 code / message、追踪 ID；不保存 API Key、签名下载地址或参考音频 base64。不要对完成或计费状态未知的超时请求自动重试。本次没有为了追索旧错误反复发起额外付费探针，也没有擅自修改或重启全局连接器。

## 164 字 / 分钟怎样校准

统计口径：汉字及读出的汉字数字，不含标点；包含句间停顿，不含结尾一秒留白。总解说为 910 个汉字，目标配音长 332.926829 秒。四段音频分别用保持音高的 `atempo` 校准，随后统一音量；`qa/speech-rate.json` 保存原长、速度系数、校准时长和实测值。

第一段明确要求慢速，同时又传入 speech_rate=-35，产生了重复减速。本版通过校准恢复目标节奏；后三段使用 speech_rate=0 后校准。`speech_rate` 是相对速度参数，并不是“每分钟字数”。第一段实际音频用本地中文 ASR 对齐；另三段使用服务返回词时间。原始 ASR 与修订记录均保留，没有把脚本文本伪装成识别结果。
