# 内容研究、文章与口播

## 内容结构：动机 30%、演化 50%、近期 20%

先定义知识点要解决的真实问题：以前的办法在哪个具体输入上失败？概念带来什么可测量的变化？给一个普通读者能跟着算或看出的例子，随后再给术语和公式。避免以定义开场后立即堆符号。

演化占一半：每次从 A 转向 B 都说明旧假设、暴露的问题、新思想与代价。公式中的每个新项都对应一个新要求；比较时沿用同一组数据和相同坐标，必要时标明量纲与尺度差异。不要把不同目标独立归一化后误当成数值优劣比较。

关键论文采用“问题 → 核心想法 → 后来影响”讲法。研究者或论文确实是转折点时可重点讲，区分最早思想、流行实现、后来的命名和应用突破，不强行为概念指定单一发明人。历史时间核对原文年份及正式发表年份。

近期研究占两成：写清检索截止日期、论文版本、原始来源及适用范围。优先作者论文、期刊/会议或官方研究页。说明与主线的关系、有什么值得追踪、局限或仍未回答的问题。明确区分论文结果与自己的推断，不能用旧经典冒充“最新”。

当前内容核实需要浏览原始来源；已有文章的纯媒体修复不要求重新做无关研究。只改链接时保留原研究核验日期，不能将发布日冒充重新核验日。

## 文章独立成立

目录 README 只做知识点导航；正文保存为 `001-introduction.md` 等独立文件。至少覆盖动机、直观例子、必要公式、历史转折、关键论文、最近进展与进一步阅读。按主题需要补充误区、可运行小实验和自测，不为了固定模板拉长文章。

正文图解保存在知识点 `assets/`，图片旁直接解释结论。SVG、图表或交互实验都可用，但文章在不播放视频时也应完整。引用靠近所支持的句子，源链接不要只收集在文末。

比例按正文知识叙述或口播主线计量；导航、参考文献、字幕符号和 CTA 不混入分母。可用 HTML 注释标记三段边界，保存汉字数/词数、时长和实际占比。叙事需要微调时允许小幅偏离，说明统计口径。

## 短视频开头与节拍

开头 3–8 秒给观众一个明确且能马上看懂的冲突，例如损失函数：“同一批数据，模型为什么会给出两个答案？换把评分尺，答案就变了。”随即用数据 1、2、3、4、20，显示平方误差偏向均值 6，绝对误差偏向中位数 3。钩子必须由后续内容兑现，不做与知识点无关的悬念。

口播用短句和可见对象。一个语义节拍只解释一个变化；观众听到“离群点拉走答案”时，画面同时突出 20、移动答案标记、改变惩罚曲线。复杂公式逐项出现，先看变了什么，再给完整表达式。

约 3 分钟是此项目快节奏范例，不是所有知识点的硬性长度。默认 320 汉字/分钟，按真实配音包括停顿计量；公式、英文缩写与数字按实际读法改写后计数。若要完整解释更复杂主题，可增加时长或拆集，保留理解所需的停顿。

片尾项目引导独立于 3:5:2 内容分配。默认用作者挥手、项目名称、GitHub 作者名和文字关注提示，不展示二维码。需要链接时使用真实 GitHub 地址；避免重复堆叠长网址。检查手机缩放后项目文字仍然可读。

## 从章节到分镜

每章先写目标、例子、关键思想、论文与结论，再拆成语义节拍。随后为每个节拍保存：

| 字段 | 用途 |
| --- | --- |
| 小节、开始/结束时间与帧号 | 可定位到最终成片 |
| 口播与实际词时间 | 决定字幕与图解出现时机 |
| 画面对象和数据 | 明确箭头、曲线、人物、道具各解释什么 |
| 起始状态、目标状态、缓动 | 定义变化，不只写“加动画” |
| 人物动作和图集帧 | 防止人物只是站在角落 |
| 验收点 | 例如最小值正确、嘴不动、字幕不遮挡 |

无需手工画出几千张静态分镜。按关键帧定义连续插值，并让每一帧能由时间重建；可以输出 `storyboard.json`、可读 `storyboard.md` 和逐帧状态日志。
