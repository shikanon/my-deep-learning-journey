# 知识点图文与解说视频

交付能独立阅读的知识点 Markdown、帮助理解的图解、可编辑视频工程和实际验收过的 MP4。用户本次要求优先；下面的默认风格来自损失函数视频最终确认的偏好。修改已有视频时只执行相关环节，无须重做全部文章或再次调用生成服务。

## 先定位现有材料

阅读仓库约定、知识点 README、文章、当前 `video/README.md` 与制作记录。确认当前成片的文件哈希，检查根目录 `assets/` 的作者形象、参考声音和动作库，优先复用。不要依据旧标签或播放器缓存选择版本。

本仓库的可运行范例位于 [损失函数 V6 工程](../03-deep-learning/loss-functions/video/loss-explainer-v6/production-notes.md)。已确认的作者动作库为 [shikanon-animation-v3](../assets/手绘形象/shikanon-animation-v3/README.md)，迁移时先检查文件和 manifest。

## 本项目的默认要求

- 内容主线按 **30% 动机与问题 / 50% 思想、公式的演化与关键论文 / 20% 最近研究与值得关注的方向** 分配。结尾项目引导单独统计。
- 开头直接呈现一个反直觉结果或具体问题，尽快说明观众看完能理解什么。讲清每次思想变化为什么发生，不把历史讲成人名清单。
- 竖屏短视频采用直观、节奏明确的讲述。解说以约 **320 汉字/分钟**作为当前默认，实测包括句间停顿；用户指定速度时以指定值为准。早期 164 字/分钟已被后续快节奏要求替代。
- 儿童手绘或可爱卡通风，中文清晰可读。可沿用 V6 暖纸色、青绿、珊瑚橙；用户另选深色背景时调整对比度。图解承担解释，装饰服从内容。
- 使用 `assets` 中的作者形象与作者参考音色。人物**保持同一张闭嘴微笑**，主要动手、脚、头部与工具；思考加问号、讲解加教棍等应贴合场景。
- 每个新动作既用于当前视频，也同步保存到根目录 `assets/` 的可复用库。统一画布与骨架锚点，消除换帧抖动；缓存存在时不重新生成。
- 顶部显示当前小节与进度。MP4 中是视觉提示；配套 HTML 播放器提供点击章节、拖动和键盘跳转。
- 视频脚注使用 **“我的深度学习之路”**，片尾引导关注 [GitHub 项目](https://github.com/shikanon/my-deep-learning-journey)。不加用户已要求去掉的“AI 合成解说”等角注。
- 视频制作源码、分镜、配音、字幕、QA 和输出均放在该知识点的 `video/` 子目录。正文插图放知识点 `assets/`；公共人物素材放根目录 `assets/`。

## 按工作阶段读取细则

1. **写文章或规划叙事：**读取 [内容与脚本](references/content-and-script.md)。核实原始论文和近期研究，明确 3:5:2 主线，先写口播，再设计逐段图解。
2. **配音、人物或道具：**读取 [动画与声音](references/animation-and-audio.md)。使用 Seed Audio 的 `generate_audio`、实际参考声音与时间戳；生成与配准人物帧时保持闭嘴和统一锚点。
3. **分镜、动效、渲染或修复：**读取 [渲染与验收](references/render-and-qa.md)。按章节、语义节拍和关键帧规划，建立可随机跳帧的确定性时间线，再核对实际编码视频。
4. **归档、清理或发布：**读取 [发布与复用](references/publishing-and-reuse.md)。只有用户已要求这些动作时才执行上传、删除或仓库发布。优先复用当地配置，凭据不进入源码与公共元数据。

涉及新位图创作时使用可用的图像生成工具并先看参考图；已有 SVG、骨架或程序绘图适合代码修改时直接修改。选择技术栈依据解释任务：HTML/SVG 擅长中文公式和图解，Canvas 擅长大量点与粒子，WebGL/Three.js 适用于确有帮助的空间演示。

## 最终验收门槛

文章可独立阅读，引用能支持对应断言；正文比例符合规划。配音确实来自要求的音色，字幕按实际语音时间对齐。作者换帧没有非预期位移、张嘴或手脚残影，动作与内容相关。

成片采用可播放的 H.264 / AAC、竖屏画幅和正确章节；完整解码通过。检查编码后的实际画面、手机排版、播放器章节与拖动，最后正常速度从头连续播到 `ended=true`，记录媒体错误、实际 URL 和最终 SHA。CLI 成功与文件存在不能替代播放验收。

上传后再检查匿名 HEAD、Range 206 和完整下载哈希，实际播放云端文件。知识点文章使用可点击封面与永久 MP4 链接；不要承诺 GitHub Markdown 内嵌交互视频。清理仅针对用户授权范围内的生成视频，保留最终文件、输入参考及复用素材。

## 可执行的发布辅助

- [publish_video.mjs](scripts/publish_video.mjs)：按内容哈希上传到独立 OSS 前缀，验证公开访问、分段读取和下载一致性，生成不含凭据的 `publication.json`；支持 `--dry-run`。
- [cleanup_generated_videos.py](scripts/cleanup_generated_videos.py)：列出或清理工程 `renders/`、`qa/` 内的中间视频；要求明确保留最终文件，并在执行时核对已发布哈希。`assets/` 输入参考不在删除范围内。

发布辅助只处理已完成的媒体，不自动发起生成、修改云服务额度、删除云端对象或推送 Git。发布步骤与验收证据详见 [发布与复用](references/publishing-and-reuse.md)。
